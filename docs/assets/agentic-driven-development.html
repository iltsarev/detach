Результат

Агент быстрее находит требования. Codex и Claude Code используют одинаковые правила.

Условие

Карта и спецификации должны быть актуальны. Тест документации проверяет их структуру.

AGENTS.md: менее 200 строк и 8 KiB · каждая спецификация: не более 12 KiB · CLAUDE.md: только @AGENTS.md

Наборы тестов

Используйте быстрый тест во время работы. Используйте full для готовности.

САМЫЙ БЫСТРЫЙ

critical

Безопасность shell и тесты состояния, владения, хранилища, питания и watchdog.

БЫСТРЫЙ

unit

Все тесты Swift без сборки приложения и анализа покрытия.

С ПОКРЫТИЕМ

coverage

Тесты Swift и минимальные значения количества тестов и покрытия.

ГОТОВЫЙ ПРОДУКТ

smoke

Новая сборка приложения, проверка Accessibility и встроенная среда выполнения.

ГОТОВНОСТЬ

full

quality-gate --mode repository запускает все автоматические проверки.

Правило: --stage, critical, unit, coverage и smoke дают диагностические результаты. Только quality-gate даёт результат готовности.

Результаты проверки

PASS относится к точной версии изменения

#01

Версия

Политика, исходный commit, базовый commit и отпечаток diff.

#02

Выполнение

Выбранные стадии, время, тип среды и статус.

#03

Файлы

Отчёт TSV, манифест, JUnit, Markdown и диагностика.

#04

Целостность

SHA-256 для отчёта и журнала каждой стадии.

#05

Возобновление

Можно использовать только результат с тем же отпечатком.

#06

Происхождение

Повторно используемая стадия сохраняет исходный запуск и время.

Эти условия всегда дают ошибку

  • Изменённые байты, commit или базовая ссылка
  • Отсутствующая или неверная хеш-сумма журнала
  • Превышение времени, прерывание или ошибка зависимости
  • Запрет sandbox или socket имеет статус environment-failed
  • Возобновление после превышения времени
  • Успешная отдельная стадия --stage

Слияние и выпуск

Локальный PASS не разрешает слияние или выпуск

ЛОКАЛЬНОФайлы задачи

Сохраните чужие изменения. Добавьте в Git только файлы задачи.

ЛОКАЛЬНОPASS

Запустите выбранные проверки и измерьте время на эталонном Mac.

GITРабочая ветка

Проверьте публичный diff. Выполните commit и push.

CIПроверка PR

Запустите ту же команду без локальных ограничений времени.

MAINСлияние

Ruleset требует успешную задачу quality-gates. Обход запрещён.

ВЫПУСКПодпись и ручные тесты

Выполните заверение Apple, реальный тест питания и выбранные ручные проверки.

УДАЛЁННОПроверка файлов

Скачайте каждый файл выпуска. Сверьте его хеш-сумму.

CI не измеряет время эталонного Mac. CI запускает все функциональные проверки и проверки минимальных значений.

Выпуск использует отдельную команду. Единственная команда выпуска — scripts/release-version X.Y.Z.

Границы автоматизации

Автоматические и ручные проверки имеют разные области

Автоматизация доказывает

  • Контракты кода и машины состояний
  • Минимальные количества тестов и значения покрытия
  • Новую сборку и изолированные интеграционные тесты
  • Установку, среду выполнения и процесс выпуска
  • Правила самого quality-gate
граница проверки

Человек и реальная среда доказывают

  • Работу Mac с закрытой крышкой
  • Реальный тест подписанных компонентов питания
  • Finder, системные разрешения и начальную настройку
  • Качество локализации и визуального опыта
  • Правильность исходного требования
Ограничение: модульные тесты и тесты синтаксического анализа не проверяют реальную работу с закрытой крышкой. Для этого нужен контролируемый тест на реальном Mac.

Применение в бигтехе

Переносите процесс и правила, а не скрипты проекта

малый контекст
+ постоянные контракты
+ выбор по diff
+ проверяемые результаты

Эта модель не зависит от Swift, macOS или GitHub Actions. Её можно применить в монорепозитории, сервисе или мобильном приложении.

Что можно применить без существенных изменений

  • Короткие правила агента и карта «задача → спецификация»
  • Разделение постоянной спецификации и временного плана
  • Одна команда готовности для локальной работы, CI и выпуска
  • Полная проверка при неизвестном влиянии
  • Запрет снижения покрытия, количества тестов и лимитов времени
  • Возобновляемые результаты, связанные с точными входными данными
  • Разделение диагностических команд и команды готовности

Что нужно добавить для большой организации

Владение

Каталог сервисов, CODEOWNERS, уровни риска и обязательные рецензенты.

Платформа

Удалённое выполнение, кеш, разделение тестов и сервис правил.

Цепочка поставки

SAST, проверка зависимостей и SBOM, подтверждение происхождения.

Обучение

Дефекты после выпуска, нестабильные тесты, ложные ошибки и время доставки.

В репозитории есть правила и проверяемые результаты. Не найдены CODEOWNERS, SAST, проверка зависимостей, mutation tests или fuzz tests.

Агент выполняет работу по правилам репозитория.

Качество зависит от четырёх условий: актуальная спецификация, подходящий тест, обязательная проверка готовности и защищённое слияние.

1 · НаправлениеОбласть изменения → спецификация → быстрый тест
2 · КонтрактРезультат, обязательные свойства, границы и проверка
3 · ВыборDiff → уровень риска → обязательные стадии
4 · СвязьCommit → отпечаток → журналы с хеш-суммами
5 · УправлениеОбязательная проверка PR и явные ручные проверки
